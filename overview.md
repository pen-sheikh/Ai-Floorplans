# TL;DR

> **"We take a floor-plan image and first extract structured information from it—walls, rooms, doors, windows, dimensions and labels. We use computer vision, image processing and OCR for that; we're not asking an image-generation AI to create the apartment. We then convert the pixel coordinates into real-world measurements and build a structured apartment model. From that model, our geometry engine generates floors, walls, ceilings, doors and windows. Three.js/React Three Fiber renders that geometry interactively in 3D. AI is a separate layer we're using for higher-level things like understanding user requests and eventually designing or furnishing rooms. The AI produces structured intent, while our deterministic geometry engine decides whether and where things actually fit."**

---

> **The 3D model is not being generated by an AI image-generation API.**
> The floor plan is analyzed/extracted into structured geometry, and then the application deterministically builds the 3D scene from that geometry.

### 1. User uploads a floor plan

The user imports:

* PNG
* JPEG
* WebP

The application processes the image **on the device by default**.

---

### 2. The extractor analyzes the image

The system doesn't ask an AI:

> "Create a 3D apartment from this image."

Instead, it performs computer-vision/image-processing steps to identify things such as:

* walls
* wall thickness
* doors
* windows
* openings
* rooms
* railings
* text
* printed dimensions

OCR is also used to read labels such as:

```text
Living Room
Bedroom 1
Kitchen
Bathroom
```

and dimensions such as:

```text
3.20 m
12'-6"
```

---

### 3. It converts pixels into real-world coordinates

The image initially only gives us pixels:

```text
wall endpoint = (428px, 712px)
```

The system determines the scale, for example:

```text
88 pixels ≈ 1 metre
```

Then the coordinates become something like:

```text
wall endpoint = (4.86m, 8.07m)
```

This is important because the 3D engine needs **real dimensions**, not image pixels.

The current priority is roughly:

```text
User-provided measurement
        ↓
Printed dimension
        ↓
Typed scale
        ↓
Estimated scale from typical dimensions
```

The source and confidence are preserved.

---

### 4. The result becomes a structured model

Instead of keeping the floor plan as an image, the application creates a structured representation.

For example:

```ts
{
  rooms: [
    {
      id: "living-room",
      name: "Living Room",
      polygon: [...],
    }
  ],

  walls: [
    {
      start: {...},
      end: {...},
      thickness: 0.20
    }
  ],

  doors: [...],
  windows: [...]
}
```

This is the **key step**.

The 3D renderer doesn't need to understand the original JPEG.

It only needs to understand:

> "Here are the walls, rooms, doors and windows and their dimensions."

---

## 5. The 3D model is generated deterministically

Once we have the structured model, Three.js / React Three Fiber constructs the scene.

For example:

```text
Wall:
2D line + thickness + height
        ↓
3D box/mesh

Room polygon
        ↓
floor mesh

Room polygon + ceiling height
        ↓
ceiling

Door position + dimensions
        ↓
3D door

Window position + dimensions
        ↓
3D window
```

So conceptually:

```text
2D geometry
     ↓
extrusion
     ↓
3D geometry
```

The same coordinates are used by both the 2D and 3D views.

That's why selecting a room in the 2D floor plan can correspond to the same room in 3D.

# Where does AI come in?

### Current core pipeline

**The core floor-plan-to-3D conversion does NOT require an AI API.**

It primarily uses:

* image processing
* computer vision
* OCR
* geometric algorithms
* deterministic reconstruction
* Three.js / React Three Fiber

> **"The AI is not generating the 3D apartment. We extract structured geometry from the floor-plan image and use deterministic geometry algorithms to construct the 3D model."**

There **is** an AI integration boundary in the project for future functionality.

For example, the user could eventually say:

> "Put a 3-seat sofa in the living room, keep 60 cm walking clearance, and make the room Scandinavian."

The AI would convert that into structured intent:

```json
{
  "room": "living_room",
  "style": "scandinavian",
  "furniture": [
    {
      "type": "sofa",
      "seats": 3
    }
  ],
  "constraints": {
    "minimumWalkway": 0.6
  }
}
```

Then the **geometry/furniture engine**, not the LLM, determines where the furniture can actually fit.

## What happens with an imperfect floor plan?

The system doesn't simply say:

> "AI understood the image."

Instead, every extracted object has **confidence and provenance**.

For example:

```text
Walls          94% confidence
Rooms          91%
Doors          78%
Windows        88%
Room label     35%
Scale          97%
```

So if the system detects a room but can't read its label:

```text
Room geometry: ✓
Room label:    ?
Room type:     Unknown
```

The room can still exist in the 3D model.
